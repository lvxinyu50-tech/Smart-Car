# test2 IPS200 实车读屏指南

## 第一次看屏幕

1. 固定车身、架空驱动轮并准备实体断电开关，烧录本工程的 `Debug/test2.hex`。上电保持 IDLE。把镜头对准实际赛道，确认 `FR` 在增加且显示 `CAMERA OK`。待机就能看两页图，两轮 PWM 应为零。
2. 保持车和赛道静止观察一次换页。**B MASK** 是默认页，**A GRAY** 是未经叠加的原始灰度图。两页都以 188×120 原比例显示。在 IDLE 和 KEY4 模式中约每 4 秒自动换页，每页都用新帧；比较时可分别拍下 FR。按键无需参与翻页。
3. 架空时按下并松开 KEY4。屏显 `VISION WAIT`，满足原有停稳与有效帧条件后进入 `VISION RUN`。此时默认会驱动两轮。车道向画面右边移动，应看到 CX 增大、ERR 为正，前轮应向右修正。先独立验证转向也可使用已有的 `VISION_STEER_ONLY=1` 配置重编译。再次按下并松开 KEY4 回待机，按住 KEY1 急停。
4. 在两种图页各做一次遮挡、急停和重新进入模式的架空测试。拍下 `FR / AGE`、视觉状态和底部故障名。帧龄达到 300 ms 会清掉过期图像。锁存故障后，用工程 README 的人工复位步骤返回待机。

## 轮廓页怎么读

| 屏上标记 | 含义 |
|---|---|
| 白底图中的白色像素、黑色像素 | 白色是通过当前亮度阈值的道路像素，黑色是背景。画面中可能同时出现多块白区，只有被算法选中的可靠区间才有绿、红边界。 |
| 绿 L、红 R | 当前采样行选中区间的左、右边界。较宽的短标是实际扫描点，细线连接相邻且均有效的点。有无效行时边界线在该处断开。 |
| 黄 MID、蓝 REF | 黄色路径来自实际参与控制的行中点。十字补线取算法使用的入口和出口路径点，经过缺失边界的段用黄色虚线。蓝色虚线固定在循迹参考列 x=94，黄线可能与它重合。 |
| 橙 BAD | 此行无效、触边、过宽或有歧义。左侧短标标出无效行；若有候选区间，橙标给出其端点。只见一侧的道路也可能出现橙标。 |
| FR、AGE、THR | FR 是所示帧的采集序号，低频显示时会跳号；AGE 是取状态时距该帧 DMA 完成的毫秒数。THR 是实际阈值。HI 使用灰度大于阈值，LO 使用灰度小于或等于阈值。 |
| ROWS、Q、W | 有效扫描行数/总行数、有效权重占总权重的百分比、有效权重和。通过路口时，普通边界行数可以下降，须同时看十字状态和补线路径。 |
| Y、L、R、CX、ERR | Y/L/R 对应从近到远第一条有效行及两端点。CX 是算法本帧计算的加权中心，十字补线生效时取补线路径的加权中心。ERR 是有效路径的 CX 减参考列。无可用误差时显示双横线。 |
| SERVO、TGT、RAMP、V L/R | SERVO 两个数依次为该帧建议的舵机占空比和最近控制节拍实际提交的占空比。TGT、RAMP 和左右轮实速单位均为 mm/s，150 mm/s 即 0.15 m/s。 |
| NEAR / MID / FAR、FAULT | 待机或视觉模式的轮廓页显示三个采样行实测中点，−1 表示该行缺少可靠中点。发生锁存故障时，底行优先显示故障原因。图像状态随新帧更新；例如画面已恢复 NORMAL 时，底行仍可能显示上一次的 FAULT VISION LOST。 |

## 用两页定位现场问题

以下阈值判断以默认亮道 HI 为例。调试时固定车辆和光照，每次只改变一个参数。

| 想判断的问题 | 对照屏幕观察 | 现场核实 |
|---|---|---|
| 阈值太高 | 灰度页仍能看见路面，轮廓页的白道变细、断开或只剩反光点；有效行减少。 | 先核对画面曝光与阴影，再小步降低阈值，观察暗处道路能否连通。 |
| 阈值太低 | 灰度页仍能区分路面与背景，轮廓页两者却连成大块白色；绿红边界消失、边缘出现橙标。 | 小步提高阈值，直到背景与白道重新分开，再复查背光路段。 |
| 选错左右边界 | 一行出现多条白带，绿红标记落在相邻道路或反光带上。若只出现橙色，说明本行已经被拒绝。 | 对照同一位置两页，记下 Y、L、R 及首次跳变的扫描行；先查阈值和画面，再查该行宽度与关联范围。 |
| 中线偏移 | 车身摆正时两条边都贴着真实道路，但黄线与蓝参考线持续分离，CX 偏离 94。 | 左右平移赛道确认 ERR 符号；再查镜头横向位置、参考列和实际舵机中值。若绿红已选错，先排查选区。 |
| 弯道前瞻不足 | 缓慢靠近弯道，远处道路在灰度图已转弯，FAR 却持续缺失或到近行才跟随。若 FAR 已提前偏移，而前轮仍迟转，应另查转向响应。 | 记录首次可见弯道、FAR 首次稳定及舵机提交改变的位置。结合远行 y、权重、镜头安装和实际车速核实。 |
| 十字误识别 | 普通弯道出现 CROSS DETECT 或 CROSS PASS。观察真实入口、远端出口是否相容，以及中间是否确有连续多行同时向两侧变宽。 | 分别记录疑似和确认帧。单帧疑似与确认通过要分开记录；在真实十字检查 PASS 后是否依次出现 REACQUIRE 和 NORMAL。 |

## 验证边界

- **ADS** 已从空 Debug 输出构建最终 ELF 和 HEX。230 个 C 编译单元，0 错误，26 个沿用的旧 UI 警告。[构建日志](build-report/IPS-Debug.log)
- **主机模拟** 使用项目的实际二值化、选区、十字状态机、调试快照、RGB565 绘制与页面调度，在模拟屏上逐像素检查灰度和阈值，并检查边界颜色与文字。覆盖同帧归属、新 DMA 覆写、模式切换、过期清屏，以及 SPI 绘图期间控制中断响应。两种配置各通过 20 个原有场景和 9 个显示场景。[结果](build-report/ips-display-checks.log) · [可复现测试包](build-report/ips-display-checks.zip)
- **实车待测** 真实曝光、画面方向、IPS 颜色与流畅度、切页时实际帧率、10 ms 中断抖动、按键至 EN 归零时延和赛道识别。可在屏幕连续换页时用逻辑分析仪测量两个 PIT 节拍和 EN。结合 Watch 的 `test_control_max_ticks` 与 STM0 频率核对最长控制临界区耗时，实际停车距离另行记录。[整车测试清单](实车测试清单.md)
